# DIYVM Local Passkey 隐私政策

生效日期：2026 年 8 月 6 日
适用版本：1.2.3 及后续兼容版本

## 1. 适用范围

本政策适用于 DIYVM Local Passkey Chrome 扩展。该扩展的单一用途是：在用户的浏览器
本地保存、管理并使用密码与通行密钥，并在用户明确选择时把加密备份保存到用户自有
阿里云 OSS。

本扩展与 Google 或 Chrome 无隶属、授权或代言关系。

## 2. 扩展处理的数据

为提供用户明确选择的功能，扩展可能在设备本地处理以下数据：

- 身份验证信息：网站登录名、电子邮箱形式的用户名、密码、通行密钥私钥、
  凭据 ID、用户句柄、RP ID 和签名计数器。
- 表单和网站信息：当前 HTTP/HTTPS 页面 Origin、页面标题，以及用户明确点击
  “读取当前表单”时登录表单中的用户名和密码。
- 用户创建的保险库内容：条目名称、别名、标签、备注、收藏状态和密码历史。
- 安全与设置数据：自动锁定时长、已授权自动填充的精确 HTTPS Origin、是否启用
  通用 Passkey、备份时间、本地风险检查结果和操作日志。
- 用户自有 OSS 配置：公网 Endpoint、Region ID、Bucket、对象路径、AccessKey ID
  和 AccessKey Secret，以及最近一次上传时间和 OSS 返回的对象标识。
- WebAuthn 请求数据：已授权 HTTPS 页面发起通行密钥操作时所需的 challenge、RP、
  用户、允许/排除凭据和验证器选项。

扩展不读取浏览历史列表、不读取 Cookie、不监控网络请求，也不收集位置、健康、
付款卡、个人通讯或广告标识符。

## 3. 数据如何使用

上述数据仅用于扩展的单一用途：

- 创建、查找、编辑、填充和删除本地密码；
- 为用户授权的 HTTPS 站点创建或使用本地通行密钥；
- 生成密码并在本地识别弱密码、重复密码和长期未更新密码；
- 执行自动锁定、加密备份、恢复和本地操作审计；
- 在用户明确启用后，测试其 OSS 连接，手动上传、检查或恢复完整加密备份；
- 记住用户主动选择的权限和界面设置。

扩展不会自动提交登录表单。密码仅按完全相同的 HTTP/HTTPS Origin 匹配，两个协议
不会互通。HTTP 网站不支持持续自动填充，用户每次手动填充前都会看到未加密连接警告。

## 4. 存储与保护

- 密码、通行密钥和操作日志使用随机 Vault Key 以 AES-256-GCM 分条加密，保存在
  Chrome 为本扩展分配的 IndexedDB 中。
- 新保险库使用 Argon2id 从主密码派生包装密钥；从旧版升级的保险库在成功解锁后
  自动迁移。主密码本身不会保存。
- 解锁后的 Vault Key 只保存在 `chrome.storage.session`，并在锁定、超时或浏览器
  会话结束时丢弃。
- 普通设置保存在 `chrome.storage.local`，不包含明文密码或通行密钥私钥。
- OSS AccessKey 配置作为独立 AES-256-GCM 加密记录保存在保险库中，不以明文写入
  `chrome.storage.local`；保险库锁定时不能执行 OSS 操作。
- 导出的备份仍保持加密，并包含 SHA-256 完整性校验；备份文件的位置和生命周期由
  用户控制。

任何客户端加密都不能消除弱主密码、恶意浏览器扩展、已被控制的操作系统或恶意网页
带来的全部风险。密码填入网页后，该网页的脚本可能读取输入框内容。

## 5. 传输、共享和出售

扩展不包含开发者服务器、分析、遥测、广告或多设备同步服务，不出售用户数据，也不
允许 DIYVM 或其他人员读取保险库。默认情况下，保险库不会发送到任何云存储。

只有当用户在扩展界面明确勾选同意、填写自己的阿里云 OSS 配置并授权该精确 Bucket
主机后，扩展才会：

- 使用 HTTPS 和 OSS V4 签名连接该用户指定的 OSS；
- 将完整但仍处于加密状态的保险库备份上传到用户指定的对象路径；
- 在用户点击检查或恢复时下载该对象，并在本地验证后处理。

DIYVM 不接收或中转这些数据，也不持有用户的 OSS AccessKey。阿里云作为用户自行选择
并控制的存储服务提供商，可能按用户与阿里云之间的协议处理网络地址、请求日志和加密
对象。断开 OSS 只删除本地加密配置和扩展权限，不会自动删除远程对象。

当用户选择填充密码或使用通行密钥时，凭据结果会提供给用户正在访问的网站，以完成
用户要求的登录操作；这是密码管理器功能本身所必需的。扩展不会向该网站发送保险库中
其他条目的数据。

扩展遵守 Chrome Web Store 用户数据政策的 Limited Use 要求：数据仅用于提供或改进
用户可见的密码与通行密钥管理功能；不用于个性化广告、信用评估、放贷或与单一用途
无关的用途。

## 6. 权限与用户控制

- `storage`：保存本地设置和临时解锁会话。
- `activeTab` 与 `scripting`：用户点击扩展后，对当前标签页执行一次性登录表单读取
  或填充。
- `alarms`：按用户选择的时间自动锁定保险库。
- HTTPS 网站：安装时不授予网站权限。用户主动开启通用 Passkey 时申请
  `https://*/*`；关闭后移除全站脚本并撤销该权限。指定网站自动填充仍按精确 Origin
  单独请求。
- 用户自有 OSS：仅在用户提交 OSS 配置时请求该 Bucket 的精确 HTTPS 主机权限；
  断开时撤销未被其他功能使用的该项权限。

用户不授予可选网站权限，仍可使用点击式密码填充。扩展不会一次申请全部网站的访问权。

## 7. 保留与删除

数据会保留在本地，直到用户删除条目、清空回收站、导入替换保险库、清除扩展数据或
卸载扩展。回收站条目仍是保险库的一部分，直至永久删除。

卸载扩展会删除 Chrome 管理的扩展存储，但不会删除用户此前下载到磁盘或上传到 OSS
的备份文件。磁盘文件和 OSS 对象需要用户自行删除。

## 8. 儿童数据

本扩展不以儿童为目标，不建立用户账户，也不会故意收集儿童个人信息。

## 9. 政策变更与联系

如果数据处理方式发生实质变化，将在扩展界面、商店说明或本政策中进行显著披露，并在
需要时重新取得用户同意。
