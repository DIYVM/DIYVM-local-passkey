# DIYVM Local Passkey 1.2.7 安全边界

本文描述扩展的实际防护、信任边界和已知限制。它是工程说明，不是独立第三方审计报告。

## 安全目标

- 本地静态数据泄露时，不直接暴露明文密码或通行密钥私钥。
- 用户未授权的网站不能获得持续的扩展页面访问能力。
- 只对完全相同的 HTTP/HTTPS Origin 填充密码，且 HTTP 与 HTTPS 不互通。
- 通行密钥请求只能来自已授权的 HTTPS 顶层页面，并满足 RP ID 与公共后缀约束。
- 密码填充和通行密钥操作始终由用户安装的扩展完成，不依赖远程代码。

## 加密与密钥

- 初始化时生成随机 256 位 Vault Key。
- 新保险库使用 Argon2id（19 MiB、2 次迭代、并行度 1、随机 128 位 salt）从主密码
  派生包装密钥。
- Vault Key 以 AES-256-GCM 包装；每条密码、通行密钥、审计日志和可选 OSS 配置
  记录也使用独立随机 IV 的 AES-256-GCM。
- 主密码不持久化。默认情况下，解锁后的 Vault Key 仅保存在
  `chrome.storage.session`，并受 5 分钟至 24 小时的自动锁定限制；关闭 Chrome 后
  会话密钥会失效。
- 用户可主动选择在本次 Chrome 会话中保持解锁。此模式只持久化偏好，不持久化
  主密码或 Vault Key；手动锁定、清除扩展数据或结束浏览器会话都会使其失效。
- 用户也可明确选择“信任此设备”。扩展生成不可导出的 AES-256-GCM 设备密钥，将
  Vault Key 包装后与设备密钥一同保存在扩展专用 IndexedDB，并在 Chrome 完全重启后
  恢复会话 Vault Key。主密码仍不保存；手动锁定会在 `chrome.storage.session` 设置
  阻止标记，使当前浏览器会话不再自动恢复。撤销信任会删除持久解锁记录，保险库恢复
  会使旧记录失效，修改主密码后则会重新包装。
- 新建或修改主密码至少需要 8 个字符；旧保险库仍可使用原主密码解锁。
- 旧版 PBKDF2-SHA-256 保险库在首次成功解锁后，用同一个主密码迁移到 Argon2id
  包装，不重建现有凭据。

Argon2id 和 AES-GCM 能提高离线攻击成本与检测密文篡改，但不能弥补弱主密码。攻击者
获得完整备份后仍可离线猜测主密码。

“信任此设备”是便利性选项，不是硬件安全边界。不可导出属性阻止网页 API 直接导出
设备密钥字节，但同一 Chrome 用户配置中的扩展仍可使用该密钥。因此，任何能够进入
该浏览器配置、控制操作系统或运行本扩展代码的人都可能在无需主密码时访问保险库；
共享电脑不应启用该选项。

## 网站访问模型

首次安装引导页不会自动获得网站权限。只有用户点击“启用通用 Passkey”后，Chrome
才会显示全部 HTTPS 网站的可选权限确认；用户可跳过并稍后在设置中开启。

### 点击式密码填充

打开扩展是明确的用户操作。`activeTab` 临时授予当前标签页 Origin 的访问能力，
`scripting` 先在可访问 frame 中查找登录框，再只向选中的同源 frame 发送凭据并执行
一次性读取或填充。页面导航或标签页关闭后临时访问结束。

- 仅处理 HTTP/HTTPS，保存和填充 HTTP 凭据时要求明确确认；
- 保存和匹配规范化后的精确 Origin；
- 优先处理当前焦点所在的登录弹窗，并扫描开放式 Shadow DOM；
- 同源 iframe 可以参与匹配，跨域 iframe 不会接收当前页面 Origin 的凭据；
- 分步登录可以先填账号，进入密码步骤后由用户再次触发填充；
- 只寻找可见、可编辑的用户名与密码输入框；
- 填充后触发标准 `input`/`change` 事件；
- 不点击按钮、不提交表单；
- 捕获必须由用户点击，并要求密码输入框已经有内容。

HTTP 页面连接未加密。扩展允许用户主动保存 HTTP 凭据，但不会为其注册持续自动填充；
每次手动填充都必须重新确认风险。该确认不能防止网络监听或页面脚本读取已经填入的密码。

### 持续自动填充

自动填充默认关闭。用户必须针对当前精确 HTTPS Origin 触发 Chrome 权限提示。扩展将
该 Origin 加入动态内容脚本列表，并允许脚本在同一 Origin 的子 frame 中运行；撤销
权限后立即移除。只有恰好一个启用了 `autoFill` 且 Origin 完全匹配的密码条目时，
才会自动填充，避免歧义。

清单包含 `https://*/*` 的可选能力。指定网站自动填充只请求精确 HTTPS Origin；只有
用户明确开启全站 Passkey 开关时，扩展才一次申请全部 HTTPS 网站权限。该设计可能使
Chrome Web Store 对更新进行更深入审核。

### 通行密钥网站访问

扩展没有必需主机权限，也不在安装时向任何网站静态注入脚本。通用 Passkey 模式
默认关闭，用户必须在设置中确认披露并授予 `https://*/*` 可选权限。关闭后移除全站
动态脚本并撤销全站权限，同时尽量恢复密码自动填充和 OSS 所需的精确
权限。页面主世界桥接、隔离世界 Content Script 和后台之间只传递受限、可序列化的
WebAuthn 数据。

- 只接受顶层 HTTPS 页面；
- 验证 `event.source`、`event.origin`、消息类型、请求 ID、大小和重复请求；
- 后台以 Chrome 提供的 `sender.url`/`sender.tab` 为准；
- RP ID 必须等于页面域名或其有效可注册父域，并通过内置公共后缀数据校验；
- 私有公共后缀、IP、跨站 RP ID 和 Related Origins 交给 Chrome 验证器处理；
- 当前只实现 ES256；
- Conditional UI 会先启动 Chrome/系统原生流程；只有保险库已解锁且 RP ID 存在匹配
  凭据时，扩展才在登录框下方显示本地账户列表。列表使用封闭 Shadow DOM，只渲染
  别名/显示名称、脱敏账号和相对最近使用时间；原始凭据 ID 只存在隔离世界内存中，
  User Handle、私钥、标签和其他保险库内容不会渲染到页面 DOM；
- 用户点击本地账户后，后台会重新验证预选凭据属于当前 RP ID 和允许列表，且仍须在
  独立扩展确认窗口批准。扩展确认窗口是最终可信确认界面，
  因为恶意网页仍可能绘制相似的页面内按钮；
- 本地和原生 Conditional UI 并行等待，最先成功的一方完成请求。本地不可用、无匹配
  凭据、不支持的算法/扩展或用户选择系统时，Chrome/系统流程继续；
- 跨域 iframe 不接管；
- 每次本地通行密钥创建或签名都显示独立确认窗口。
- 确认窗口同时显示调用页面 Origin 与 RP ID；选择“改用 Chrome / 系统”会调用网页
  原始的 WebAuthn 方法，“取消本次操作”则终止整个请求。

## 备份与恢复

- 备份包含加密后的保险库快照和 SHA-256 完整性校验。
- “验证备份”检查格式、大小、字段、密文结构和校验值，不解锁或导入。
- 导入采用完整替换，防止半导入状态；导入后保险库保持锁定。
- 校验和用于发现损坏，不是攻击者不可伪造的数字签名。保密性仍依赖主密码和加密。

### 用户自有阿里云 OSS

- 默认关闭，不连接 DIYVM 或其他开发者控制的服务器。
- 用户提交配置时才申请该 Bucket 的精确 HTTPS 主机权限。
- AccessKey Secret 只作为加密保险库记录持久化；锁定后不能签名 OSS 请求。
- 后台按 OSS V4 规范签名，只上传现有加密备份，不上传解密后的单条凭据。
- 下载后先执行 20 MB 大小限制、UTF-8、备份结构和 SHA-256 完整性检查，再允许恢复。
- 断开会删除加密配置并撤销未被其他功能使用的权限，但不会删除远程对象。

固定对象路径的再次上传会覆盖当前对象；应由用户在 Bucket 中开启版本控制，以便恢复
旧版本。OSS 功能是手动远程备份，不实现多设备合并或实时同步。获得远程备份的攻击者
仍可离线猜测主密码；OSS 权限泄露也不在扩展能够完全消除的风险范围内。

## 本地审计

弱密码、重复密码和长期未更新检查完全在解锁后的本地执行。操作日志作为加密记录保存，
最多保留 500 条，记录事件类型、时间和条目标识，不记录明文密码、私钥或完整备注。

## 不在防护范围内

- 已被控制的操作系统、Chrome 配置文件或同时拥有扩展权限的恶意软件。
- 启用“信任此设备”后，能够进入同一 Chrome 用户配置的其他本机使用者。
- 用户解锁期间能够读取进程内存的攻击者。
- 恶意或被攻陷的网站在密码已经填入其 DOM 后读取该密码。
- 网站脚本可能观察到页面内 DIYVM 候选列表的宿主元素、尺寸或用户交互，并据此推断
  当前已解锁 Vault 对该 RP ID 存在匹配凭据。列表中的别名/显示名称、脱敏账号和相对
  使用时间是有意提供给用户的页面内可见信息，不应被视为浏览器原生 UI 级别的保密数据；
  原始凭据 ID、User Handle 和私钥不会渲染到页面 DOM。
- 钓鱼网站诱导用户保存新的凭据；精确 Origin 防止跨域匹配，但不能判断品牌真伪。
- 弱主密码、用户泄露备份、屏幕录制、键盘记录和社会工程。
- 用户配置权限过大的 OSS AccessKey、关闭 Bucket 版本控制或自行删除远程对象。
- 浏览器或依赖项中尚未公开的漏洞。

## 发布前安全门槛

每个正式包应满足：

1. `npm ci` 与 `npm audit` 无已知依赖漏洞。
2. `npm run test:pure` 全部通过。
3. Manifest 无 `key`，无远程代码，无非预期权限。
4. 商店包不包含 source map、测试数据、私钥或本地保险库。
5. 在 Chrome 120+ 实机验证初始化、锁定、本地/OSS 备份、点击填充、权限授予/撤销
   和通用 Passkey 回退路径。

项目完成代码级检查并不等于独立第三方渗透测试或密码学审计。
